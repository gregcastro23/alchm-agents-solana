# ASOL ↔ WTEN contract

The request contract between **ASOL** (this repo, `agents.alchm.kitchen` + `api.agents.alchm.kitchen`)
and **WTEN** (`gregcastro23/WhatToEatNext`, `alchm.kitchen`). Written **from the code**, not from
either side's notes. ASOL paths are relative to this repo at branch `feat/wten-sync-contract`; WTEN
paths are `gregcastro23/WhatToEatNext@master` as read on 2026-09-22 (after WTEN #866–#868 merged).

"Planetary Agents" / "PA" / `planetaryAgentsApi` in WTEN code and older docs means ASOL.

### Shared retry policy (`lib/wten/delivery.ts`)

- Retried: timeouts, network errors, 5xx, 429 (honouring `Retry-After` up to 10s; longer ends the
  delivery), and a 409 whose body says `status: "in_flight"` (WTEN's `src/lib/hooks/dispatcher.ts:69-71`).
- Never retried: other 4xx. 409 without the in-flight marker = already applied on sync-credit /
  sync-debit / sync-event; 402 is final.
- Endpoints WTEN does not dedupe (`sync-event`, `feed`, `agent-recipes`) retry **only** failures
  that never reached the handler: 429, 503, and connect-phase errors (`ECONNREFUSED`, `ENOTFOUND`,
  `EAI_AGAIN`, `UND_ERR_CONNECT_TIMEOUT`). A 500 or timeout there may already have been applied.
- Backoff: equal jitter in `[cap/2, cap]`, `cap = min(4s, 250ms·2^(n-1))`, 3 attempts, and never past
  an optional caller deadline. Attempts are logged as `[wten-delivery] {json}` without headers.
- Fail-fast: once a delivery exhausts its attempts without any response (timeouts, network errors),
  every delivery in the next 60s makes a single attempt; any response clears it. The agent tick
  delivers per agent in sequence, so an unreachable WTEN costs one timeout per call, not three.

## 3. Every place the two secrets are used interchangeably

The intended split: `ALCHM_KITCHEN_SYNC_SECRET` in `X-Sync-Secret` for the economy and agent-sync
routes; `INTERNAL_API_SECRET` as `Bearer` for feed and service calls. These sites cross it:

1. `lib/security/internal-auth.ts:37-41` — `hasInternalApiSecret` expects `INTERNAL_API_SECRET || ALCHM_KITCHEN_SYNC_SECRET`, presented in **any** of Bearer / `X-Sync-Secret` / `X-Internal-Secret`. Used by `/api/solana/health`, ASOL's own `POST /api/feed` (`app/api/feed/route.ts:216`), `/api/cron/purge-guest-chats`. Consequence for WTEN: a 401 from `/api/solana/health` means "the apps don't share `INTERNAL_API_SECRET`" only when ASOL has `INTERNAL_API_SECRET` set.
2. `backend/main.py:1996-2004` (Python agent-sync) — reads the `X-Sync-Secret` header (the `ALCHM_KITCHEN_SYNC_SECRET` header everywhere else) but compares it to `INTERNAL_API_SECRET`. WTEN matches this: it sends `X-Sync-Secret: INTERNAL_API_SECRET` (`src/app/api/admin/agent-sync/route.ts:76`).
3. `app/api/internal/group-chat/route.ts:29-43` — same crossing: `X-Sync-Secret` compared to `INTERNAL_API_SECRET || PA_INTERNAL_API_SECRET`; WTEN sends `X-Sync-Secret: INTERNAL_API_SECRET` (`src/app/api/agents/group-chat/route.ts:117`).
4. `lib/wtenClient.ts:42` — `INTERNAL_API_SECRET || ALCHM_KITCHEN_SYNC_SECRET`, sent as Bearer for the weekly-menu calls.
5. `lib/agents/feed-pusher.ts:49` — `INTERNAL_API_SECRET || WHATTOEATNEXT_API_KEY`.
6. `backend/main.py:2072` (Python purge cron) — `PA_CRON_SECRET || CRON_SECRET || INTERNAL_API_SECRET || ALCHM_KITCHEN_SYNC_SECRET`.
7. `backend/main.py:2128` (synthetic MCP probe) — `PA_CRON_SECRET || INTERNAL_API_SECRET`.
8. `backend/main.py:2336` and `pa-rust-backend/src/config.rs:52` — `PA_INTERNAL_API_SECRET || INTERNAL_API_SECRET`.
9. `scripts/run-asol-solana-service.ts:97,215` — `SOLANA_SYNC_WEBHOOK_SECRET ?? ALCHM_KITCHEN_SYNC_SECRET`, sent as Bearer.
10. WTEN `src/app/api/internal/agent-recipes/route.ts:51-52` accepts **either** secret.
11. `lib/backend.ts:291` — sends `INTERNAL_API_SECRET` to a third host (WTEN's Railway backend) in a header named `INTERNAL_API_SECRET` (underscores; some proxies drop such headers).

`pa-rust-backend` loads `internal_api_secret` (`src/config.rs:52`) but no route compares it.
