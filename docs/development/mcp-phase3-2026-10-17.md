# MCP Phase 3: typed contracts and official transport

Implemented October 17, 2026. This records local source and native-binary verification; it is not a deployment or registry-publication record.

## Result

The nine existing tools now use shared Pydantic request/result contracts. Discovery advertises generated `inputSchema` and `outputSchema`, input validation precedes identity lookup or provider work, and successful handler output is validated before returning. `structuredContent` and the legacy JSON text block carry the same payload. Publication validation preserves the exact reviewed menu rather than injecting defaults that change its fingerprint.

The handwritten stdin/stdout loop is replaced by the official Python SDK `mcp==2.3.0`. A thin adapter uses the SDK's low-level `Server` callbacks so the existing project dispatcher can retain its authorization, telemetry, resource/prompt behavior, and legacy credential layout. The low-level API does not automatically enforce advertised tool schemas; the shared domain boundary explicitly validates them. It does not duplicate SDK framing, lifecycle, discovery, or cancellation handling.

The desktop probes modern discovery and uses legacy initialization only after `-32601` (unsupported method). It validates negotiated capabilities/version, attaches the appropriate metadata, prefers structured results, rejects tool errors, and retains JSON-text compatibility. Asynchronous writes are awaited; timed-out calls send cancellation and clear timers. Ambiguous tool mutations are not automatically replayed. Events from a replaced child cannot clear the replacement connection.

## Contracts and trust

- All nine tools have object-shaped input/output schemas. Requests have field bounds plus a 128 KiB JSON guard; results are bounded to 1 MiB, and flexible JSON has depth limits. Exact limits live in `backend/mcp_contracts.py`.
- Standard credentials use `params._meta`; older `arguments._meta` remains accepted. Conflicting credential values fail before remote work. Only normalized `apiKey` and bounded `caller` metadata enter handlers/telemetry. Protocol and arbitrary metadata stay outside that business boundary.
- Phase 2 identity, signed conversation ownership, private chat, draft-only planning, publisher roles, and stable publication keys remain in place.
- Handler/output failures return tool errors; invalid arguments return invalid-parameters errors. Internal adapter failures and rejected tool names do not echo submitted values. This does not constitute a complete private-prompt retention/logging redesign.
- Chart-duel provider calls are awaited as one group, so cancelling the parent cancels both children. Partial failures are explicit; both provider calls failing produces a tool error.

## Packaging and checks

The project now requires Python 3.11+. The pinned SDK release itself declares Python 3.10+; 3.11 is this project's runtime/build choice. Runtime dependencies, including Pydantic and the SDK's transport dependencies, are pinned with platform markers and hashes in `backend/requirements-mcp.lock`. Build tooling pins PyInstaller 6.22.3. Native and existing Intel build environments verify the applicable lock before freezing. The frozen spec includes the validation core rather than excluding it.

The standalone smoke harness keeps stdin open while each response arrives, avoiding cancellation caused by premature EOF. It uses temporary storage (`PA_MCP_DATA_DIR` for frozen telemetry), clears credentials/database URLs, disables the adjacent MCP bridge, and uses local-only tool/resource fixtures. It checks all nine tools, typed input/output discovery, invalid arguments, dual-result equivalence, and graceful EOF shutdown. Release CI runs that harness against each native artifact. Its macOS matrix uses explicit `macos-15` (arm64) and `macos-15-intel` (x64) labels from the [official runner image table](https://github.com/actions/runner-images#available-images).

Verification completed on the integrated source snapshot:

- **399 backend tests passed**, with the opt-in subprocess test skipped in that normal run. Five existing Chroma deprecation warnings remain.
- **37 desktop transport/parser tests passed**; scoped strict TypeScript checking passed. The Tauri transport is mocked for those tests.
- Clean-wheel closure/import/contract checks passed within the backend suite.
- Ruff and shell syntax checks passed; Markdown/TypeScript/YAML formatting and diff checks passed.
- A clean, hash-locked Python runtime and a locally built **macOS arm64 PyInstaller binary** pass the standalone protocol smoke harness. Other native targets are covered by the updated CI configuration, not claimed as locally executed.
- The opt-in real stdio chat test passed separately (one test) with a mock loopback backend; it performs no provider or public-publication request.

Tests are run from isolated source snapshots where cold local files would otherwise stall tooling. No production database, provider spend, external publication, or deployment is required by these checks. This is not a whole-desktop/Tauri release build or a whole-application TypeScript verification.

## Remaining roadmap

Phase 4 still needs shared execution/evidence snapshots, bounded bridge concurrency, sanitized/pinned child launches, explicit deadlines/budgets, and correlated tracing. SDK request cancellation is now a foundation, not proof of durable work or of cancellation support in every adjacent service. Invocation audit storage remains; tracing does not automatically replace it.

Phase 5 still needs owned durable council runs, critique/synthesis, restart recovery, and budget/termination tests. A live Python task is not a durable workflow. The separate LangChain memory, Rust placeholders, OS credential storage, and network policy work remain separate follow-ups.

WTEN publication receipts, complete versioned exports, and source-grounded nutrition are covered by the [WTEN integration prompt](wten-agent-integration-prompt-2026-10-16.md). The earlier 1,000/1,099 recipe count and 298 missing-nutrition entries describe a historical PA snapshot. Missing nutrition must remain unknown until source-backed calculation supplies it.
